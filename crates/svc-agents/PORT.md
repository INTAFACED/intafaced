# svc-agents in Rust: the port notes

Each slice of svc-agents' move to Rust starts here, in a fresh thread. `services/svc-agents` stays the service that runs until the switch; nothing is served from this crate in any stack yet. This crate holds the shell every slice builds on:

- `src/door/`: every call `router.ts` serves (193), who may call each, the checks its own middleware runs before the input, its input check (`schemas.json`, run by the kit's zod engine with `src/refines.rs`), and the person checks its handler runs first after the input. Past those a call answers "the `<slice>` slice is not ported" (500). `health` is the door's own and is served.
- `src/env.rs`: the environment, held to `env.ts` by `tests/env_parity.rs` (47 environments).
- `src/errors.rs`: `AgentError` (every `AgentErrorCode`, listed in `src/errors_table.rs`) and `toTRPCError`, the main router's guard.
- The store (slice `store`): `src/db.rs` (one pool, `search_path` `agents,public` and the service's `application_name`, the transaction helper; `DATABASE_SSL=true` refuses to start, as the kit's pool has no TLS), `src/migrate.rs` and `migrations/` (the 43 migrations of `services/svc-agents/drizzle`, byte for byte, run by the kit's runner: `svc-agents migrate [--down]`), `src/boot.rs` (the schema check and the boot upsert of `src/boot_agents.json`, the ten rows the TypeScript boot writes), `src/timers.rs` (the timers `index.ts` starts, their periods and owners, and the loop that drives one) and `src/main.rs` (the binary, in `index.ts`'s boot order). The door holds the store and passes it to every slice.

`scripts/record-door.mjs` writes the recorded files from the TypeScript: it runs each call's middlewares on probe callers to read its checks, and sends each call a valid input from callers that differ in one thing to read its handler's first person checks. Its `--check` fails when a written file is stale. Run it with the workspace packages built (`pnpm --filter "@intafaced/svc-agents^..." build`).

## What the shell holds, and how it is proved

- `tests/wire_replay.rs` sends every request of `services/svc-agents/wire-replay.golden/` (193 calls, five inputs, five callers: 4,825 answers) to the door. Every answer the door decides is held byte for byte: route and method refusals, 401s, scope, region, service and person 403s, input 400s, and `health`. Any other answer is owed by its call's slice while the door answers "not ported", counted per slice. `WIRE_REPLAY_SLICE=<slice>` prints a slice's owed answers; `WIRE_REPLAY_STRICT=<slice>` fails while it owes any. A slice is done when its strict run passes.
- `tests/input_parity.rs`: 5,971 inputs over the 193 calls, each against zod's own verdict.
- `tests/env_parity.rs`: the environment, value for value and refusal for refusal.
- `tests/store_pg.rs`, on a real Postgres (`TEST_DATABASE_URL_AGENTS` or `TEST_DATABASE_URL`): the binary's `migrate` up, re-run and `--down`, every table below, the schema check, the boot upsert (an operator's switch survives a reboot), the pool's session settings and transactions, `/health` and `/ready`. `services/svc-agents/src/fleet/boot-agents-rust.test.ts` fails while `src/boot_agents.json` is not the TypeScript boot's rows.

## The doors

The checks run in the TypeScript's middleware order (`src/door/mod.rs`):

1. route and method (`GET` for a query, `POST` for a mutation; no batching);
2. who may call:
   - a scoped call: a signed-in principal (401), then `scopedProcedure`'s guards: with `person: true` a service on the request is refused ("A signed-in user session is required"), then the scope (`agents:read`, `agents:execute`, `admin:read` or `admin:write`, with the kit's interactive-only and two-factor rules), then the region (`module: 'agents'`);
   - `usage.settle` and `usage.settleSession`: a verified service that is svc-agents itself (`requireSettleService`);
   - `own.policy.forService`: a verified service, svc-trade only (`serviceProcedureFor`);
   - the eight public calls are checked by nobody at the door: `health`, the six `policy` reads (`coach`, `copyIntel`, `merchant`, `navigator`, `scanner`, `support`), and `own.identity.agentCall`, whose handler checks the agent's own token;
3. the call's own middleware before its input: a key or a sub-account refused with the call's own code (`agents.execute_person_only` for every `executeProcedure`, `agents.select_person_only`, `agents.fleet_person_only`, `agents.alerts_person_only`, `agents.log_read_person_only`, `agents.route_change_person_only`), or the Coach run's three checks;
4. the input;
5. the handler's first person checks (`assertPersonSetsLimits`, the team's `assertPerson`): a key, a sub-account, or a session without `identity:write`, refused as "A signed-in user session is required";
6. the slice.

A service on the request is judged as `createEdgeContext` judges it: by its own key when `S2S_AUTH_MODE` is on, else by the shared secret (at least 32 characters), the body bound (`require`).

## What the calls share

- **The runtime** (`runtime.ts`, `AgentRuntime`): sessions, the guardrail bound to each, the `agent_actions` audit trail every log and desk reads, usage windows and their settlement. Nearly every slice reads it; `runtime` ports it first.
- **The gateway** (`gateway/`): the routing table (configured, plus founders' overrides from `route_overrides`), the provider adapters (`providers/`: the mock engine and the upstream described only by `AGENTS_UPSTREAM_*`), and each task's rate. No vendor is named in code or answers (`pnpm scan:brand`).
- **Metering** (`metering/`, `spend/`, `funds.ts`): exact per-user usage in `usage_records` and `usage_windows`, spend caps and reservations, billed once per window through the ledger. In Rust the charge goes through svc-ledger's `postRecipe` door with the ledger-client recipe it names (as svc-academy's port does), never an entry built here; the idempotency key is the window's business key. svc-agents holds no balance.
- **The guards**: the main router's `toTRPCError` (`src/errors.rs`); each sub-router (`own`, `team`, `spend`, `fleet`, `oplog`, `alerts`, the route desk, the on-chain routes) has its own guard mapping its refusals, ported with its slice.
- **Owner values**: a blank one stays blank and its call refuses with its own code (`agents.*_unset`, `owner.decision`); none is invented. `tier-laws.ts` (`AGENTS_TIER_LAWS`) gates the scanner, navigator and support doors.
- **Calls out**: svc-ledger (`LEDGER_URL`: balances and `feeCharge`), svc-identity (`IDENTITY_URL`: affiliate accrue and payout, session reads, linked wallets, the owner's self-freeze), svc-academy (`ACADEMY_URL`: the coach's curriculum), svc-support (`SUPPORT_URL`), svc-trade (`TRADE_URL`: tickers, prices), svc-pay (`PAY_URL`), svc-bank (`BANK_URL`: team membership and usage payment), each signed as svc-agents.
- **Callers**: the customer app and the admin console through svc-edge's `/trpc` proxy, svc-trade (`own.policy.forService`, `venue/own-agent-policy-client.ts`), and svc-agents itself (`usage.settle*`).
- **Timers and consumers** (`index.ts`): the transcript purge (hourly), the unpublished sweep (every minute), the alert evaluation, the background ticker (`AGENTS_BACKGROUND_STEP_MS`), the schedule workers (`AGENTS_SCHEDULE_TICK_MS`, `AGENTS_SCHEDULE_WORKERS`) and the trigger consumer. Boot upserts the five product factories' guardrails into `agent_definitions` (`fleet/boot-register.ts`).

## Where the port cannot be the TypeScript's

- A JSON syntax error in `AGENTS_UPSTREAM_HEADERS` or `AGENTS_UPSTREAM_MODELS` (other than an empty value) is refused with the kit's parser's words, not V8's. The boot refuses either way.
- tRPC batching is not served, as in every Rust door.
- A refused `AGENTS_ROUTING_TABLE` stops the boot with this crate's words, not zod's.
- The gateway's streaming call is not ported: nothing in the TypeScript calls `gateway.stream`, and the kit's `fetch` reads a body whole. The adapters still declare `stream` as the TypeScript's do, so `/ready` reports the same capabilities. The gateway's engine spans (`withEngineSpan`) are not emitted yet.
