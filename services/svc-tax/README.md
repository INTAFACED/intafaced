# svc-tax

Per-jurisdiction lot export over ledger reads. **Not** a second money book, **not** a CSV re-import, **not** counsel.

Blank owner `TAX_JURISDICTION_MAP_JSON` refuses `tax.jurisdiction_unmapped`. Caller selects `FIFO|LIFO|HIFO` for the pack — no silent country default. Empty books return an empty pack, never a fabricated `$0` PnL. Missing lot/cost-basis is named unknown (`tax.cost_basis_unavailable` / `tax.lot_underflow`) — never an invented pairing or a `0` basis. Amounts are decimal strings. Completeness is OWNER map: packs stamp `complete: false` and residual `tax.export_incomplete`; `complete: true` is refused. Never invent jurisdictions.

A year pack lists each sub-account's fills and converts with `fee` and `makerRebate` in separate columns. Realised gain on a line is proceeds minus that line's cost basis, and only when both are present. A null basis stays null on that sub-account, stays in `tax.cost_basis_unavailable`, and is not copied onto another sub-account. Rows outside the owner-published `TAX_HISTORY_YEARS` window are left out. The ledger history wire has no sub-account parent index, fee, maker rebate, or cost basis, so boot leaves `subAccountBooks: "unwired"` and invents no rows until both readers are attached.

## API

| Procedure              | Scope       | Input                             | Output                                                                      |
| ---------------------- | ----------- | --------------------------------- | --------------------------------------------------------------------------- |
| `health`               | public      | —                                 | `{ ok, service }` — liveness, not a custody claim                           |
| `exportPreview`        | `tax:read`  | `{ lotMethod }`                   | preview; amounts as strings                                                 |
| `exportPack`           | `tax:read`  | `{ lotMethod }`                   | JSON pack (`bodyBase64`), including `subAccounts`                           |
| `lotBook`              | `tax:read`  | `{ method? }`                     | profit and loss indicator from the caller's own fills (see below)           |
| `missingBasis`         | `tax:read`  | `{ method? }`                     | open lots and disposals with no basis; effect is `unknown share`            |
| `pnlOverTime`          | `tax:read`  | `{ from, to?, utcOffsetMinutes }` | the indicator over a date range and its breakdown (see below)               |
| `basisOverride.set`    | `tax:write` | lot, price, date, note            | customer-entered basis, or a manual position held apart from balances       |
| `basisOverride.remove` | `tax:write` | `{ lotId }`                       | tombstone; the book shows the unknown again                                 |
| `setLotMethod`         | `tax:write` | `{ assetId, method }`             | the caller's method for the account (`assetId` null) or a coin; null clears |
| `setDayMethod`         | `tax:write` | `{ day, assetId, method }`        | the caller's method for one UTC day, one coin or all (`assetId` null)       |
| `pickSaleLot`          | `tax:write` | `{ saleTxId, assetId, lotId }`    | the lot one of the caller's sales draws on first; `lotId` null clears       |
| `setIncludeTransfers`  | `tax:write` | `{ include }`                     | whether deposits and withdrawals count in the figures; null clears (on)     |

`basisOverride.set` refuses `tax.basis_store_unwired` when `DATABASE_URL` is blank, `tax.basis_price_unset` when the price is blank, and `portfolio.basis_override_not_allowed` when the lot already has a cost from our fills or a market price. A set `DATABASE_URL` whose `DATABASE_POOL_MAX` is blank refuses at boot with `tax.database_pool_max_unset` and does not open a pool. The size is never filled in. The same payload twice stores one version. The key is `basisoverride:<userId>:<lotId>:<version>`. A manual position id is `manual:<userId>:<token>` and is not added to holdings. While any customer basis is active, the year pack carries `tax.customer_basis_export_unset`: whether those figures may appear in a regulator-facing export is not published. Figures that use an override are marked `customer-entered`. An override never posts to the ledger.

## Lot book (profit and loss indicator)

`lotBook` is a self-only read of the caller's own ledger, labelled `indicator_not_tax_advice`. It is not the year pack and is not gated by the jurisdiction map. Without a method it applies the caller's saved choices (below); `{ method }` (`FIFO`, `LIFO`, `HIFO` or `AVERAGE`) previews that one method for every sale (`preview: true`, no saved choice or pick applied). Anything else refuses. `missingBasis` takes the same input and reads the same book.

**Saved choices.** The caller may save a method for the whole account, for one coin, and for one UTC day (one coin or all), and pick the lot one sale draws on first. A sale's method, most specific first: that coin on that day, every coin that day, the coin, the account, then the product default FIFO; each sale says which (`method`, `methodSource`). A picked lot is drawn first (as much as is still open); the rest goes by the method. A pick must name a sale in the caller's own book and a lot of that coin still open at the sale, or it is refused (`tax.lot_pick_invalid`); a saved pick whose lot is no longer open at the sale (another choice changed what earlier sales used) is named (`tax.lot_pick_unusable`) and the method decides. Choices are settings rows in schema `tax` (`drizzle/20261024110000_cost_basis_choices.sql`), keyed by the caller; they move no value and post nothing. `DATABASE_URL` unset: the book uses the default and says `choices: { status: 'unwired' }`, and a save refuses `tax.basis_store_unwired`. Choices that cannot be read just then: the book answers with the default and says `choices: { status: 'unavailable' }` (`tax.choices_unavailable`).

**Lots.** Every arrival of a coin is a lot with an id (`lot:<txId>:<asset>`, then `:2`, `:3` when one transaction credits the same coin again), when it arrived, its source (`trade`, `deposit`, `reward`, `transfer_in`, `other_in`), quantity, what is left, its cost and the cost of what is left, and days held. A bought lot is joined from two ledger reads, the received leg (on `available`) and the paying leg (on that order's `hold` account), on the transaction; against USDT, USDC or USD it has a real dollar cost (the fee is already out of the received leg). Fills against a house quote (`trade.fill.mm_maker`) and a customer maker's sale to the token buyback (`trade.fill.buyback`) are read like any other fill. Dollar coins count as exactly 1 USD and are not lots. Released holds, reversed withdrawals, margin release, unstake, earn withdrawals and fee corrections are the customer's own coins coming back, not new lots.

**Moves between the customer's own accounts (LB-6).** A move of coins between the main account and one of the customer's named spaces, or between two spaces, carries the lots: they keep their acquired date, source and share of basis, and each part that moved is a lot in the account it reached (`spaceId`, and `carriedFrom` naming the lot it came from and the move). A move is not a sale and not a new lot. Lines are paired only inside one ledger transaction (one credit on an own account and one debit on another, same coin and amount), so a deposit and a withdrawal in different transactions are never paired. Which spaces are the customer's comes from svc-bank (`spaces.ownedAccounts`, `BANK_URL`; svc-tax never reads the spaces table); each space's history is read from the ledger as its `subaccount` account. Lots move oldest first; a move with too few open coins behind it carries what there is and the rest arrives with no basis, named. Sales are trades and draw on main-account lots only. `held` and the reconciliation are the main account. `BANK_URL` unset: the book follows the main account only and says `spaces: { status: 'unwired' }`; no answer from svc-bank: `spaces: { status: 'unavailable' }` and `tax.own_spaces_unavailable`.

**Value on arrival.** A lot that was not bought is valued at the price when it arrived, read from svc-trade's public candles (`TRADE_URL`): USDT market, else USDC; the close of the last one-minute candle that opened at or before the arrival, else the last hourly or daily candle that had already ended by then. Never a later price, never today's price, never zero. The market, candle size and candle time are returned so the screen names the source. No price (or no `TRADE_URL`) leaves the value null with `tax.price_at_time_unavailable`.

**Cost of an arrival** is the owner's `TAX_DEPOSIT_BASIS`: `market` (the value on arrival) or `customer` (unknown until the customer enters one). Blank: unknown, with `tax.deposit_basis_policy_unset`.

**Sales.** Each sale lists the lots it used (`matches`). A part that draws on a lot with no cost has unknown cost and result; HIFO and AVERAGE are unknown as a whole when any open lot has no cost. A sale bigger than every open lot is `unmatchedQty` (`tax.lot_underflow`). AVERAGE restates the open lots at the pool's average exactly.

**Withdrawals (LB-4).** A withdrawal of a coin (`withdraw.held`, the coins leaving `available` for a `withdraw:<id>` hold) is a disposal of kind `moved_out`, matched to lots by the same method as a sale, at its value when it left (price at time, as above; no price leaves it null with `tax.price_at_time_unavailable`). Each withdrawal has its own hold account, so its lines are read from that account (found in the caller's account list) and pair there, never by amount or time: what left is what was held less what went back (`withdraw.reversed`: all of it when the rail failed, the rest of a partial card capture), and what went back is neither a disposal nor a new lot. The coins sitting in a withdrawal hold are not counted as held. Dollar coins are not lots, so their withdrawals are not disposals.

**Deposits and withdrawals in the figures (`includeTransfers`).** On (the default, and when nothing is saved): a deposit or transfer in is a lot whose cost follows `TAX_DEPOSIT_BASIS`, and a withdrawal counts as `moved_out` at its value when it left. Off: lots from deposits and transfers in, and withdrawals, are left out of cost, realised and unrealised, and kept in a pool of their own: a sale draws on the other lots first (ranked, averaged and picked among them alone) and reaches those lots only for quantity the others do not cover, and a withdrawal draws on them first, so a deposit's cost never reaches a trade's under any method. They stay listed with `counted: false` (a lot or match) or `counted: 'none' | 'part'` (a disposal), and an asset's `uncountedQty` names the open quantity left out. Moves between the customer's own accounts never change a figure either way. Saved per caller in `tax.pnl_settings` (`drizzle/20261024150000_pnl_settings.sql`); the book says which it used (`includeTransfers`).

**Fees.** `historyPage` names the fee each fill took from the caller's receiving line (svc-ledger). A sale and a bought lot carry it (`fee`: the coin, the amount and its dollar value, or `unknown` when the ledger did not say). The fee is already out of what was received, so it is inside the cost of a bought lot and inside the result of a sale; it is shown, never subtracted again. `feesUsd` is the dollar total of the fees inside the figures (a sale left out entirely leaves its fee out); null when any is unknown. A later fee correction is its own history line.

**Over time (`pnlOverTime`, J-portfolio-05 #4-#5).** The cumulative result at each moment of a range, worked out from the same book, never stored: the result of the counted sales made by then (a sale is matched with only what came before it, so its result does not change later) plus, for each coin, what the counted main-account lots open then were worth then less their cost. The open lots are rebuilt from the book (each lot from when it reached the main account, less what sales and moves had taken from it), which lands on the book's own open lots at the book's time under every method. The price is the close of the last candle that had ended by then on the coin's USDT market, else USDC, read once per coin from svc-trade (`TRADE_URL`) in the finest size that fits the chart (at most 400 points) and one read to now (5m, 1h, 4h, 1d, 1w); only a live end uses the candle still open. A moment where a held coin has no price, or a cost or a result is unknown, is null with what is missing named (`no_price`, `cost_unknown`), never zero. The change over the range (`periodUsd`) is split by coin, by market (each market's sales in the range, plus `held`, the price move on what is held) and by day in the caller's time zone (`utcOffsetMinutes`; up to 400 days, else `byDay: null`); each split adds up to it exactly or the read refuses `tax.pnl_breakdown_mismatch`. `feesUsd` is the fees inside the period's figures. A range that ends in the future ends now; an empty one refuses `tax.pnl_range_invalid`, one that starts too long ago to price `tax.pnl_range_too_long`, and market data that cannot be read `tax.pnl_prices_unavailable`. Each sale names its `market` (the coin sold over the coin received).

**Honesty rules.** If an asset is held in a different quantity than its open lots, which lot is open is not known, so its cost, unrealised and sale results are null (`tax.lot_book_unreconciled`). Hitting the read ceiling is `tax.lot_book_incomplete` and no figure is shown. Short or long term is not classified: the term rule is not published (`termClass: null`, `termRule` names `tax.term_rule_unset`). Unrealised value is the caller's to join with current prices.

## Events

None. This service publishes no subjects.

## Ledger

Read-only toward the ledger. `balances` + `history` over `@intafaced/ledger-client` HTTP to svc-ledger. No recipes. No `post`. Customer basis rows are this service's own table and are not balances.

| Read       | Why                                   |
| ---------- | ------------------------------------- |
| `balances` | current available books               |
| `history`  | lot reconstruction for those accounts |

Data lake / indexer missing → named `absent` on the pack (`tax.data_lake_unavailable`, `tax.indexer_unavailable`). A set URL is `configured` + `tax.data_lake_unprobed` / `tax.indexer_unprobed` — never `ok`. Never filled in as `$0`.

## Service keys: ledger reads

The ledger reads (balances and history) are signed with svc-tax's own key when `S2S_AUTH_MODE`, `S2S_SIGNING_KID` and `S2S_SIGNING_KEY` are set (`dual` also sends the shared secret, `keypair` the key only); unset, they are signed with the shared secret as before. Setup and rotation: `services/svc-ledger/CALLER-BINDING.md`.
