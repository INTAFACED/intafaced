# svc-mining-pool

**Mining pool: share ingest, PPLNS payout planning and epoch payouts.** Shares arrive on `POST /submitShare` and are stored per window; the epoch job plans a PPLNS split and pays it through the `rewardPay` ledger recipe. This service holds no balance: value moves only through svc-ledger.

Signed-in reads for the Mining room (`overview`, `connection`, `probe`) publish only what the owner set. A blank overview, host, port, probe limit or probe timeout refuses with `mining.overview_unset`, `mining.connection_unset`, `mining.probe_limit_unset` or `mining.probe_timeout_unset`. The probe opens a TCP connection to that host and port only, stores nothing, and stops at `mining.probe_limit_reached`. No mining password is returned.

## The miner door (stratum-style, TCP)

A rig connects to the host and port the Mining room shows, and speaks one JSON request a line (`src/stratum-door.ts`): `mining.subscribe`, then `mining.authorize ["<account id>.<worker name>"]` (the account id and worker name the room copies; no worker name is the `default` worker), then the pool sends `mining.notify` with the job (the window id, the pool's own header for that window, account and rig, and the published proof-of-work parameters). `mining.submit ["<user>", "<job id>", "<nonce>"]` goes through the same checked ingest as `POST /submitShare`: the pool checks the work and weighs it 1, and a refused share keeps nothing (`mining.pow_invalid`, `mining.share_duplicate`, `mining.job_stale` with a new job, `mining.stratum_unauthorized`, `mining.account_invalid`, `mining.stratum_malformed`, `mining.stratum_method_unknown`). A line longer than 4096 bytes closes the connection.

The door opens only when the owner publishes `MINING_STRATUM_LISTEN_PORT`, `MINING_STRATUM_WINDOW_SECONDS` (60 to 2678400; windows count from the Unix epoch) and `MINING_STRATUM_ASSET_ID`; any blank keeps it closed and the log says `mining.stratum_unset`. With no published proof-of-work parameters `mining.authorize` refuses `mining.pow_spec_unset`: the door takes only work the pool can check. Testnet work earns no credit (`mining.testnet_no_credit` at payout).

## Service keys: inbound share ingest

`POST /submitShare` names the caller from its own service key when `S2S_AUTH_MODE`, `S2S_KEYRING` and the signing pair are set: `dual` accepts the key and the shared secret, `keypair` the key only. Unset, the shared secret works exactly as before. A key-signed call that fails is refused and never retried against the shared secret. `/trpc` is unchanged: it names no service caller. Setup and rotation: `services/svc-ledger/CALLER-BINDING.md`.

## Workers: connectivity, state changes, maintenance and alert limit

The miner door keeps no lasting connection, so a worker is **online** exactly while its newest accepted share is younger than the owner's quiet interval, `MINING_WORKER_QUIET_SECONDS` (10 to 86400), measured on the database clock; otherwise it is **offline**. Its **state** is `maintenance` while it is in maintenance, else `offline` when quiet, else `active` (`src/worker-state.ts`).

- `workers.one({ workerId, windowMinutes })` (`ledger:read`, the caller's own worker; another's is `mining.worker_not_found`) answers hashing (`hashing` when an accepted share is in the window, else `idle`), the window's accepted weight, connectivity, the last share time, state, the quiet interval, the alert limit and since when the worker is in maintenance. A blank quiet interval refuses `mining.quiet_interval_unset` (out of range: `mining.quiet_interval_invalid`).
- `workers.stateChanges({ workerId })` (`ledger:read`) answers the recorded online/offline changes, newest first (at most 100), and `evaluatedAt`, the evaluator's last look at that worker.
- `workers.setMaintenance({ workerIds (1..50), on })` (`trade:write`) puts the caller's own workers in maintenance or takes them out; any id that is not the caller's refuses the whole call. One row per worker (`mining:maintenance:<workerId>`); asking again keeps the first `since`. `workers.maintenance()` (`ledger:read`) lists them.
- `workers.setAlertLimit({ workerId, mode, limit? })` (`trade:write`): `automatic` is the owner's published share of the worker's trailing accepted weight in the read's window, `MINING_WORKER_ALERT_SHARE_BPS` (1 to 10000 basis points, worked out in exact decimals); `manual` is the account's own value above zero; `null` clears the choice. Neither is a default: no choice, or automatic with a blank share, answers `alertLimit: null` with `mining.alert_limit_unset`; automatic with no share in the window answers `no_shares_in_window`. A bad value refuses `mining.alert_limit_invalid`.
- `workers.mine` rows carry `state` (maintenance always; active or offline only with a published quiet interval, else null with `stateReason`).

A change between online and offline is recorded once, keyed by a business key (`mining:worker-offline:<workerId>:<newest share ISO>`, `mining:worker-online:…`), so a repeat evaluation or a second evaluator writes nothing new. A worker in maintenance, or one that never sent an accepted share, gets no row. `workers.one` and `workers.stateChanges` settle the one worker they read the same way before answering, so the change is there when the room first says offline; only the evaluator stamps `evaluatedAt`.

**The evaluator** runs every `MINING_WORKER_EVALUATE_SECONDS` (1 to 3600) when that, the quiet interval and Postgres are all present, apart from the epoch payout job (`MINING_PAYOUT_INTERVAL_MS`); it moves no value. Otherwise it stays off and the log says `[workers] evaluator off: <code>` (`mining.worker_evaluate_unset`, `mining.quiet_interval_unset`, `mining.pg_unavailable`). The local test stack runs it with the LOCAL TEST values in `tooling/profiles/test-owner-values/mining-pool.json` (quiet 60 s, evaluate every 10 s); the automatic alert share stays blank there.
