### 2. Money as `number` anywhere?

**NO for money amounts. Policy/LTV use integers (not money).**

| Kind                                      | Representation                                       | Evidence                                                                              |
| ----------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Principal, collateral, proceeds, interest | `Amount` (bigint) via `parseAmount` / `formatAmount` | `loan-service.ts:7-15`, `toLoan` principal `parseAmount` at `:1523`                   |
| Wire / SQL money columns                  | decimal strings / `numeric(38,18)`                   | `packages/db` `amount()`, router `amountString`                                       |
| APR / LTV / penalty / tranche bps         | `number` integers                                    | `toProduct` `Number(row.*_bps)` at `loan-service.ts:1498-1508` — policy, not balances |
| LTV output                                | integer bps (or `MAX_SAFE_INTEGER` if unsecured)     | `risk.ts:116-129`                                                                     |
| Mark deviation bps                        | `Number((delta * 10000n + …) / previous)`            | `prices.ts:185` — ratio of prices in bps, not a balance                               |

Risk arithmetic is bigint throughout (`risk.ts:1-36` header + `ltvBps`/`dailyLoanInterest`/`planLiquidation`/`splitProceeds`). No `parseFloat` on money in `src/loans/`.

### 3. Liquidation atomic / fail-closed?

**Mostly YES for seizure+sale; NO full atomicity for shortfall cover.**

| Step                                   | Atomic?                               | Fail-closed?                                        | File:line                                                      |
| -------------------------------------- | ------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------- |
| Seize + sell + allocate proceeds       | **One** ledger post (`loanLiquidate`) | Yes — insufficient buyer cash fails post            | recipe `loans.ts:295-384`; service `loan-service.ts:1214-1256` |
| No counterparty                        | N/A                                   | **Yes** — throws `bank.no_liquidation_counterparty` | `loan-service.ts:1187-1193`                                    |
| Unusable mark (stale / last / breaker) | N/A                                   | **Yes** — `mark-refused`, no sale                   | `loan-service.ts:1069-1070`, `prices.ts:160-201`               |
| Empty reserve on draw                  | N/A                                   | **Yes** — `bank.loan_reserve_underfunded`           | `loan-service.ts:514-523`                                      |
| Empty insurance on shortfall           | **Second** post after settle          | **Partial fail** — see finding B-01                 | `loan-service.ts:1260-1283`                                    |
| Crash mid-tranche                      | Claim row + idempotent key            | Re-drive safe for liquidate post                    | `loan-service.ts:96-103`, `1420-1460`                          |

Ordering guarantee (margin call + grace before liquidate; insolvency waives grace): pure `planLiquidation` (`risk.ts:423-435`) + service sweep (`loan-service.ts:953-973`).
