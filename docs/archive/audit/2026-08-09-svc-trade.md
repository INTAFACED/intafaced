## Broken, fixed here

### F1 · Fee-exhausting match left permanent unposted fills (money)

**Promise:** README “if this crashes exactly here” table and settleFill header: fills may be ahead of the ledger; re-run heals via `trade.fill:<fillId>`.

**Falsification:** `tradeFill` / `marketMakerMakerFill` throw when `mulBps` ceil makes fee ≥ receivable (legal on `markets_dust_free_ck` which only requires tick×lot ≥ 1 wei). `settleFill` inserted legs **before** the recipe. Re-run re-inserts (idempotent) then throws again. `remainingHold` treats the unposted fill as consumed → cancel under-releases → funds stranded in the order hold pot. Ledger-client documented the recipe refuse; svc-trade still wrote the rows.

**Fix:**

- Pure `fillReceivablesSurviveFees` / `fillPayAmounts` in `spot/fees.ts` (must agree with the recipe).
- `TradeService.assertFillFeesPostable` runs on **both** classic and house-MM settle paths **before** any fill insert.
- New code `trade.fee_exceeds_fill` (tRPC 500 / CCXT ExchangeError — operator alarm, not bot retry bait).
- Tests: pure agreement with recipe; Postgres integration asserts zero fill rows + intact maker hold (CI when DB up).
- README crash-table honesty updated.

**Not claimed fixed:** listings that can still _produce_ a 1-wei feeable fill — refuse is correct; dust×fee product policy is separate (could tighten CHECK later).

## Broken, parked (not product-law inventing)

### R1 · Funding period membership (ledger-vs-margin on replay)

**Where written:** `funding-settlement.ts` header “KNOWN RESIDUAL”; `BUILD-STOP-TRADE-2026-08-08.md`.

**What is true:** keys are stable for a fixed open set. A position opened between a failed tick and its replay adds a new `(period, payer, payee)` key. Ledger posts the extra leg; `applyFundingNets` is idempotent on `(position, period)` and does not re-net the original payer for the second plan’s total → same family as #1034/#1047 (ledger ahead of margin row).

**Proof test:** `funding-settlement.test.ts` — “documents membership residual: a new position mid-period adds a new ledger key for the same period”.

**Why not fixed here:** needs a decision on what period membership **is** (open-as-of-period snapshot vs open-now). Not inventable on a residual audit PR.

### R2 · Futures `PositionService.open` is not client-idempotent

**What is true:** `positionId = randomUUID()` every call; margin lock key is `futures.margin.lock:<positionId>`. Timeout + retry opens a **second** position and double-locks margin. Spot place avoids this via `clientOrderId` → deterministic order id → same hold key.

**Why not fixed here:** needs a published client position id / intent key contract (wire + store + rejection of second open). Direction residual, not a silent UUID hash.

### R3 · Copy fee-share invents protocol fee from notional×bps

**What is true:** `attributeCopyFeeShare` does `mulBps(followerFillNotional, protocolFeeBps, 'floor')` then sweeps that share from the **shared** `houseFees('trade', asset)` pot. Actual `tradeFill` fees:

- use **ceil** bps,
- are taken from the asset each side **receives** (base vs quote), not always quote notional.

So the attribution can disagree with the fee row that settled. When §8 law is unpublished the path refuses (safe default). When published, a bad notional/bps pair can over-claim the house pot (draining other fills’ fees) or under-pay the leader.

**Why not fixed here:** wiring should bind to `fills.fee_amount` / fee asset of the real fill; law still blank in prod config. Documented for the ship that turns §8 on.

### R4 · README claimed `orders_hold_positive_ck` still forbids unfunded rows

**What is true:** `0000` had `hold_amount > 0`. Paper `0006` replaced with `hold_amount >= 0` so paper/sim rows need no ledger post. Live place still posts positive holds; the CHECK alone no longer makes “unfunded open” unrepresentable.

**Fix landed as doc honesty only** (service path still correct for live).
