# Local test stack

> **Not current rules (2026-10-17).** This file stays only because tooling reads its path. Current rules: [`AGENTS.md`](../AGENTS.md). Where this file disagrees with AGENTS.md or the code, AGENTS.md and the code win.

One command starts a private copy of the INTAFACED backend and the Customer app on your Mac, without Docker. Everything binds to `127.0.0.1`. Balances and market prices in it are **test funds and test prices, not real money or a live market feed**; the Customer shows a fixed banner saying so.

## Commands

| Command                                              | What it does                                                                                                                                                                                                                     |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm local:stack`                                   | Start (safe to re-run) and print a health table. First run builds and sets up the database; allow a few minutes. `--rebuild` forces a rebuild.                                                                                   |
| `pnpm local:stack:stop`                              | Stop only the processes this script started (checked by pid file and command line), then Postgres. Data is kept.                                                                                                                 |
| `pnpm local:fund <email-or-userId> <ASSET> <amount>` | Credit test funds, e.g. `pnpm local:fund me@example.com USDT 1000`. Decimal strings only.                                                                                                                                        |
| `node tooling/scripts/local-test-stack.mjs status`   | Health table only.                                                                                                                                                                                                               |
| `pnpm local:stack:plan`                              | Read-only: every service, port, database schema and where Edge sends each route. Changes nothing (`--json` for a machine-readable copy).                                                                                         |
| `pnpm local:stack --only token,p2p`                  | Start only the named services (plus Postgres and NATS). Anything already running is left alone.                                                                                                                                  |
| `pnpm local:stack:restart edge`                      | Stop the named services, then start whatever is not running. Use after Edge's wiring changes; other services and their data stay up.                                                                                             |
| `pnpm local:stack customer-dist <abs path>`          | Serve the Customer app from another folder (for example a redesign build under review). Saved, so `start` and `restart` keep it. `customer-dist` alone shows it; `customer-dist --clear` goes back to this checkout's own build. |

### Serving a different Customer build

`LOCAL_STACK_CUSTOMER_DIST=<absolute folder>` (in the shell) or `pnpm local:stack customer-dist <absolute folder>` makes the Customer server on 3210 serve that folder instead of `apps/customer/dist`. While it is set, the script never builds the Customer app (so an unrelated `restart trade` cannot replace the build being reviewed) and never writes into the folder. The folder must be an absolute path, exist, contain `index.html` and sit under your home folder (symlinks are followed before that check); otherwise the command refuses and says why.

The choice is saved in `~/.intafaced/local-test-stack/customer-dist.json` (mode 600). A value in the shell is saved too the next time `start` or `restart` runs, and the shell value wins over a saved one. `status`, `plan` and the end of `start` print which folder is active. The Customer server looks the folder up on every request and reads files per request (no caching), so setting, changing or clearing it takes effect at once with no restart, and rebuilding files inside the folder shows on the next reload. If the folder later disappears, the server answers 503 with the reason instead of falling back to another build. After `--clear`, the next start rebuilds the Customer app if the last build skipped it.

Open **http://127.0.0.1:3210** for everything except passkeys.

**Passkeys (Touch ID): open http://localhost:3210.** A passkey is bound to a hostname, and browsers refuse an IP address as the relying-party ID, so the stack serves the same app on `localhost:3210` too (LOCAL TEST: Identity runs with `WEBAUTHN_ENABLED=true`, relying-party ID `localhost`, origin `http://localhost:3210`; Edge allows both origins). Sessions and passkeys are per origin: a passkey enrolled on `localhost` does not exist on `127.0.0.1`, and you sign in again on each. In Security, add a passkey; later sign in or step up with it.

## Ports

Postgres 15460 · NATS 14232 (monitor 18232) · Edge 14500 · Ledger 14501 · Identity 14502 · Token 14503 · Trade 14504 · Matching 14505 · Pay 14506 · Agents 14507 · P2P 14508 · Bank 14509 · Notify 14510 · Academy 14511 · Support 14512 · Market 14513 · Blueprint 14514 · Quant 14515 · Execution 14516 · Tax 14517 · Mining pool 14518 · Ops 14519 · Customer 3210 · Invitation site (apps/invitation) 3220 · Founder console (apps/admin) 3100. Ports 3200, 3401, 3162, 3340, 5432, 15440 and 15444 are not used.

State lives in `~/.intafaced/local-test-stack/` (data, logs, `secrets.json` mode 600, `LOCAL-TEST-STACK.json` marker). Requires PostgreSQL 16 at `/opt/homebrew/bin` and at least 14 GB free disk.

For a fresh database without altering an existing one, set `export LOCAL_STACK_STATE="$HOME/.intafaced/my-fresh-test-stack"` before running any command. The path must be absolute. Stack, funding, market, gates and world commands all use that folder, including background children. Use the same setting for later status, restart and stop commands. Ports stay fixed: stop the previous stack with its original state setting before starting another. The old data and secrets stay in their original folder; nothing is copied automatically. `plan --json` reports `stateDir` so the selected folder can be checked before starting.

Helpers also check that this folder's Postgres and recorded services still own their loopback ports, with the expected checkout, database directory and process start time. A stale marker cannot authorize mutations against a different stack that has taken over the fixed ports. Missing ownership evidence refuses the action before account creation, funding or order submission.

## Real vs test

Real: the code. Identity, Ledger, Trade, Matching, Pay, Bank and Edge are the repository's own services, running their own migrations against a real Postgres and a real NATS JetStream. Funds move only through the ledger (`packages/ledger-client` recipes into `svc-ledger`); amounts are decimal strings on the wire.

Test: the money. `local:fund` posts a `deposit` recipe on rail `local-test` with reference `LOCAL-TEST-<timestamp>-<id>`, so every entry is labelled. It refuses unless the marker file exists and the database is `127.0.0.1` on the stack's port. No bank, card, chain or exchange feed is connected. Prices, bank cards, on-chain Pay, WebSocket (`/ws` returns 503) and loans' price marks are unavailable. Background money jobs in Bank (scheduled transfers, auto-invest, interest, loan accrual) are switched off.

Placeholders the services refuse to boot without (no owner-published value exists): reconcile cadence, rate limits, Pay checkout limits (from `.env.example`), Bank `LOAN_QUOTE_ASSET_ID=USDT` and batch sizes `1` (jobs off), Matching snapshot cadence `0` (off). They are local-test values, not product decisions. Edge's kill-state file is written once as an explicit all-on list; without it Edge halts every module.

## Every Customer door is reachable

Edge answers `502 Connection unavailable` for any route whose service is not running, so the stack starts all 18 backend services the Customer app calls: besides Ledger, Identity, Matching, Trade, Pay and Bank, also **Token** (Token room), **P2P**, **Academy**, **Support**, **Market**, **Notify** (Notifications), **Agents** (Navigator), **Blueprint**, **Quant** and **Execution** (Trade tools), and **Tax** (profit and loss, the lot book over ledger reads). Each is one Node process on `127.0.0.1`, gets the same secrets as the others (edge principal, internal service secret, screening pass-through) and its own Postgres schema and role (`svc_<name>`); Execution and Tax have no tables. `pnpm local:stack:test` fails if any route in `services/svc-edge/src/routes.ts`, or any module the Customer app calls, points at a service the stack does not start and is not listed (with a reason) in `EDGE_ABSENT` in the script.

"Reachable" means the door answers with the service's own responses. These parts stay **not connected** on purpose, because they need a real outside provider or an owner decision, and the service says so by name instead of inventing an answer:

Local-test instrument key (p2p only). The p2p process sets `LOCAL_TEST_KMS=1` and `LOCAL_TEST_KMS_DIR` to `<state>/p2p-kms`. The first boot writes `p2p-instrument.local-test.key` there, mode 0600, and seals new instrument details as `{"_sealed":"local-test:v1:..."}`. This is not owner KMS. `P2P_FEE_BPS=0` is an explicit LOCAL TEST free cut, the same kind of published zero as `MARKET_HOUSE_COMMISSION_BPS=0` in `.env.example`: `trades.take` posts a 0 bps cut, so the buyer receives the whole amount, instead of refusing `p2p.fee_bps_unset`. Undo: unset `LOCAL_TEST_KMS` and `LOCAL_TEST_KMS_DIR`, then `pnpm local:stack:restart p2p`. After that restart a sealed row refuses with `p2p.instrument_kms_required` and is not returned as account details. No other service gets either variable.

## A fresh stack, or a cloud container (root)

A wiped state folder trades only after five steps, in this order, and shows Earn, Loans and P2P working after a sixth (Try it and the journeys workflow run the same):

```sh
pnpm local:stack                                         # services up; the founders enrol
node tooling/scripts/local-test-stack.mjs restart matching # matching reads its operator seats at start
node tooling/scripts/local-test-gates.mjs apply           # lifecycle publication, then the markets open
pnpm local:market                                        # refuses closed markets; creates its two TEST accounts
node tooling/scripts/local-test-gates.mjs verify          # verifies those accounts, so their quotes are accepted
LOCAL_TEST=1 node tooling/scripts/local-test-seed.mjs apply --state "$LOCAL_STACK_STATE" # TEST earn pools, loan products, P2P method
```

The first BTC/USDT trade, and so the first candle, follows within about a minute. Without the last step Earn and Loans show their honest empty states ("No earn rates are configured", "No loan products yet"); see [Local test content](#local-test-content).

### Windows (through WSL)

The stack runs on Linux, so on Windows it runs inside WSL 2:

1. Install Ubuntu on WSL (`wsl --install -d Ubuntu` in PowerShell) and work inside it, with the repository cloned into the Linux home folder (not under `/mnt/c`).
2. Use Node `^20.19.0` or `>=22.12.0`. That is rolldown's engine range: on any other version pnpm skips rolldown's Linux build and the Customer build fails.
3. Point `LOCAL_STACK_NATS_BIN` at a Linux `nats-server` 2.10.24 (the release's `linux-amd64` archive). The stack itself carries only a verified `darwin-arm64` archive.
4. Then follow the steps above, the same as in a Linux container.

### Chart history

A wiped stack has no past trades, so a chart asking for 200 fifteen-minute bars has nothing to draw. To give it history, stop the market maker before `verify`, then write the history and start the maker again:

```sh
pnpm local:market stop                                   # after its accounts exist, before verify: nothing trades yet
node tooling/scripts/local-test-gates.mjs verify
node tooling/scripts/local-test-market.mjs history       # 210 bars of TEST trades per market, moved into the past
pnpm local:market                                        # live quotes carry on from the last history price
```

`history` places real TEST trades now, through the same door and ledger as the market maker: a post-only maker order and an immediate-or-cancel taker order at the same TEST price, two trades per bar on the same price walk, with client ids starting `LTEST-TAPE-`. It then calls svc-trade's signed LOCAL TEST route, which moves those fills' times into the past, evenly inside 15-minute bars, the newest bar ending where the current bucket starts. Prices, amounts, fees, orders and ledger entries keep what they were. That gives 210 fifteen-minute bars, each with its own open and close, and about 53 hourly ones. Trade n of three markets at a time goes in one maker request and one taker request (svc-trade's `POST /api/v1/orders/batch`, where each item takes the single-order path), so each market still gets the same trades in the same order, and the lanes of three run side by side (two for the six default spot markets). It sends at most 14 requests a second, under Edge's local budget of 1200 a minute; six markets take under five minutes on a 4-core machine, where the services' own speed, not that budget, sets the pace. It ends by waiting out the rest of Edge's one-minute window after its last request, so whatever runs next on the stack starts with the whole budget. `--bars`, `--step-minutes`, `--trades-per-bar` and `--markets` change that.

svc-trade has that route only with `TRADE_LOCAL_TEST_TAPE_RETIME=on`, which the stack sets, and refuses to start with it outside `APP_ENV` dev or test (`services/svc-trade/src/spot/local-test-tape.ts`). It refuses any market that already has a trade that is not a tape trade. So `history` skips every market with trades and says so. On a long-lived stack, wipe the state folder for history.

As root (a cloud container's default user), `initdb` and `postgres` refuse to run, so the stack runs them as the OS user `postgres` (`LOCAL_STACK_PG_USER` names another) through `runuser`, and gives that user the database folders. That user cannot enter `/root`, so set the state folder outside it, for example `LOCAL_STACK_STATE=/var/lib/intafaced/local-test-stack`; the stack refuses with that hint otherwise. The container also needs a `nats-server` binary (`LOCAL_STACK_NATS_BIN`) and the screening variables below in its environment.

## Try it (a temporary link, TEST money)

The `Try it` workflow (Actions, Try it, Run workflow) boots this stack on GitHub's runner the same way Real-app journeys does. It then gives a password-protected link to the Customer app for up to about 5 h 45 min (owner decision 48; the ADR amendment is in `docs/adr/2026-08-08-staging-deploy-path.md`). The link is in the run summary. The password is the repository secret `TRY_PASSWORD`; without it, the run refuses before it boots.

- **The gate.** `tooling/scripts/try-it.mjs gate` sits between the tunnel and the Customer server. It shows a password page and sets a SameSite=Strict, HttpOnly, Secure cookie; with ten wrong tries in a minute it stops taking passwords for that minute. Every other request needs the cookie. The gate refuses any Host other than the link's own and any Origin other than the link's. Before forwarding, it rewrites Host and Origin to `http://127.0.0.1:3210`, so the Customer server's Host guard and Edge's `EDGE_ALLOWED_ORIGINS` stay unchanged.
- **The start page** (`/__try/`, behind the password):
  - the demo account: `try-demo@local-test.invalid`, with the same password, verified and funded with TEST USDT by `try-it.mjs demo`;
  - a TEST inbox showing the codes and links the stack "mails" to its outbox file;
  - a button for the two TEST operators to approve waiting verification requests;
  - a once-per-account TEST USDT credit, through `local:fund` with a business key per email.
- **Not on the link:**
  - live streams (no svc-ws, as in the journeys run);
  - the founder console;
  - passkeys (their relying party is localhost);
  - anything that needs a partner.
- **One rate limit.** Everyone on the link counts as one caller against Edge's 1200 requests a minute.
- **Checks.** `node tooling/scripts/try-it.test.mjs` checks the gate in front of a fake app. `try-it.mjs check <link>` checks a running link; the workflow runs it before posting the link.

## Founder console

`pnpm local:stack` also builds the founder console (`apps/admin`, a production Next build, rebuilt only when `apps/admin`, `packages` or the lockfile change) and serves it on http://127.0.0.1:3100 against the stack's Edge, with `APP_ENV=dev` (a local http origin is accepted only in dev or test) and a session key generated once into `secrets.json` (`adminSession`). The local test founders sign in with their entries in `founders.json`; operator journeys use `apps/customer/tests/real-app/admin.mjs`, which reads `JOURNEY_ADMIN_URL` (default http://127.0.0.1:3100). `--only admin`, `restart admin` and `stop admin` work like the services. Log: `logs/admin.log`.

The console's treasury doors (the ledger freeze and the reconciliation controls' define, change and run) travel on `ADMIN_TREASURY_TOKEN`, which founder sessions never carry. When the stack starts the console it signs `local_test_founder_a` in with their second factor and mints `admin:treasury` on that fresh session for 24 hours (`consoleTreasuryToken` in `tooling/scripts/local-test-gates.mjs`). The stack's own JWT secret signs it, so it is a LOCAL TEST credential valid on this stack only. The stack passes it in the console process's environment and never writes it to disk. A start that finds the console with no token, or less than an hour left on it, mints a new one first and only then restarts the console; if that mint fails, the start says why and leaves the console as it was (a console with no token shows those doors parked). Each mint signs founder a in once more, with the next TOTP step identity accepts: a step no local tool has used yet, the current one or, inside identity's one-step skew window, the one after it. It waits for the clock (up to 30 seconds) only when both are spent. The gates commands sign each pair in once per command. If founder a's session is revoked or the founder pair is enrolled again, `restart admin` mints a new token. The start's last lines say until when the console holds one.

**Invitation site and the outreach intake.** `pnpm local:stack` also builds the public invitation site (`apps/invitation`, built once and again on `--rebuild`) and serves it on http://127.0.0.1:3220 like the Customer app, with `/api/*` passed to Edge. Its join and partner enquiry forms reach svc-ops (port 14519, schema `ops`), which runs here with a LOCAL TEST `OPS_OUTREACH_CONFIG`: the local test founder pair, a one-day continuation and Monday to Friday 09:00 Europe/London review, none of them owner decisions. svc-ops starts before the founders enrol on a fresh stack, so it restarts once after they do (and again if the pair changes). Its founder notifications are not wired here (no `NOTIFY_URL` or `OPS_NOTIFY_SERVICE_SECRET`), so an enquiry is recorded in the CRM and its notification stays unsent. A founder's CRM token (`ops:read`, `ops:write`) is `crmToken()` on `local-test-gates.mjs` `approverSessions`; `apps/customer/tests/real-app/outreach.mjs` creates an invite campaign and its source key and reads a campaign's totals. `--only invitation`, `restart invitation` and `stop invitation` work like the services. Log: `logs/invitation.log`.

## Screening

Edge refuses **every** `/api/*` call, including sign-up and sign-in, with `edge.screening_unset` (HTTP 503) until a sanctions screening list is set. This script never sets or invents one. It passes `INTAFACED_SANCTIONS_REGIONS` and `INTAFACED_SANCTIONS_LIST_SOURCE` to Edge from the shell environment, or else from the machine-local file `~/.intafaced/local-test-stack/screening.local.json` (`{"regions": "...", "source": "..."}`), which is never committed. Without either, it prints a warning and every call returns 503. See `services/svc-edge/src/geo-block.ts` and `packages/config/src/screening.ts`.

On Nitro's Mac (approved by Nitro, 13 Oct 2026) that file holds a labelled local test fixture. It is not counsel's list and must never be copied to staging or production. Commas separate entries, so keep any explanation in `source`, not in `regions`.

## Living test market (prices, book, fills)

`pnpm local:market` / `pnpm local:market:stop` / `node tooling/scripts/local-test-market.mjs status`. It makes Trade look alive on this stack only: a labelled test account `test_market_maker` keeps a ladder of post-only bids and asks around a deterministic synthetic **TEST PRICE** (BTC/ETH vs USDT and USDC, IFC/USDT; `--markets all` adds commodities; `--seed N`, `--interval S`, `--levels N`), and a second account `test_taker` occasionally crosses the best level so recent trades and candles exist. Log: `~/.intafaced/local-test-stack/logs/market.log`. Credentials of the two test accounts: `~/.intafaced/local-test-stack/market-accounts.json` (mode 600).

Real vs test: orders go through Edge `/api/v1` into svc-trade and svc-matching, and the accounts are funded by `local:fund` (svc-ledger deposits, rail refs `LOCAL-TEST-MM-...`). Nothing writes a balance, fill or price into a database. Ticker, order book, trades and candles on the Customer are derived by svc-trade from the book and the fill tape (`services/svc-trade/src/public-rest.ts`), so there is no separate price feed to drive. Prices are invented starting points, not a feed.

Supervision (the market stopped silently twice overnight and prices froze for 30+ minutes): `pnpm local:market status` shows the pid, `ok`, `STALE` (alive but no log line for 2 minutes) or `DOWN` (it was started and its process is gone; exit code 1), and `pnpm local:stack status` has a `market-maker` row with the same words. Every way the process can end writes an `EXIT pid N code C: reason` line to the log (signal, uncaught exception, unhandled rejection, normal stop); a SIGKILL or power cut cannot be logged, and then `status` shows STALE or DOWN. `pnpm local:market ensure` starts it again with the same options only if it was started before and is not running now; `pnpm local:stack` and `pnpm local:stack:restart` call it after the services are up. A pid file plus a start lock keep it to one copy. `pnpm local:market stop` is the one way to say "leave it off": it forgets the market so ensure does not restart it. A stray word (`pnpm local:market foo`) is refused instead of starting anything.

Containment: it refuses unless the state directory and `LOCAL-TEST-STACK.json` exist and every target URL is `http://127.0.0.1:<a port the marker lists>`. Test: `pnpm local:market:test`.

Preflight: before the stand-ins below existed, three gates stopped every order, and the script reads them (GET only) and refuses with their names instead of sending failing orders: (1) Edge refuses new orders because svc-matching `/health` carries no halt flag (`edge.venue_halt_unavailable`); (2) no market-lifecycle publication exists, so svc-trade refuses every order (`trade.lifecycle_authority_unavailable`); (3) svc-matching holds no book until a first order, and svc-trade will not admit that first order (`trade.matching_market_missing`). Until these are resolved the script prints them and exits. In the Customer the market picker lists every active market but opens on the first one alphabetically (AUD/USD, which is also not orderable), which is why only AUD/USD appears to show.

## Local test stand-ins (option B, approved by Nitro on 2026-10-13)

On this stack only, the stack may stand in for three people who do not exist locally. Every record carries the label **"LOCAL TEST — not a real approval"** and a `local-test:` marker, and no service code is bypassed.

`node tooling/scripts/local-test-gates.mjs apply` (also: `operators | futures | lifecycle | open | terms | assets | deposit-terms | verify | status`) does, in order:

0. **TEST perpetual and derivatives terms.** It lists the labelled TEST perpetual `BTC/USDT:USDT` (`test = true`, from `services/svc-trade/fixtures/btc-usdt-swap.TEST.json`, through `tooling/scripts/seed-futures-test-listing.mjs`, which refuses a real listing of the same symbol), then the two founders publish a TEST risk agreement and TEST margin terms for the stack's region `XX` and a one-question TEST quiz through svc-trade's own admin doors (one proposes, the other approves; texts in `tooling/scripts/local-test-futures-terms.mjs`). Futures orders go through the futures book (`TRADE_FUTURES_MATCHING_ENABLED=true`, band 5%), the perpetual is marked from the `BTC/USDT` book (`TRADE_FUTURES_INDEX_SPOT_MARKETS`), and the TEST market maker quotes it through `POST /api/v1/futures/orders`. No agreement or quiz gates a futures open (owner decision 2026-10-27); the TEST rules still name the identity tier (`full`) an open needs. Its quotes are most of the TEST book's depth, so they sit in the top tier of the TEST maintenance ladder: the maker names that tier (`confirmTier`), as a trader does in the ticket's confirm step when an order moves a position into a higher tier. The perpetual also carries TEST open-interest limits on its operator limits row (`TEST_FUTURES_OI_LIMITS` in `local-test-gates.mjs`: 1000 BTC, half of it per account), since a futures open on a market with no published open-interest limit refuses. No dynamic price range is published, so the 5% band stays in force; a journey sets one with `local-test-gates.mjs risk BTC/USDT:USDT priceRangeMax=… priceRangeTrigger=… priceRangeCadenceSeconds=…` and clears it after. The futures conditional job runs every 2 s (`TRADE_FUTURES_CONDITIONAL_JOBS_ENABLED`), so a take-profit, stop-loss or stop can be armed, and one that fires places a reduce-only order in the futures book against the maker's quotes. None of these are owner or legal values.

1. **Owner publishes the market lifecycle.** For each orderable 24/7 crypto spot market it posts a real publication to svc-trade's signed internal route `/internal/market-lifecycle` (HMAC with the stack's `INTERNAL_SERVICE_SECRET`).
