## The bug shape that keeps recurring

**A service constructs its router and never mounts it. `/health` answers 200,
the container is healthy, the fleet is green, and every procedure 404s.**

This has now happened three times:

1. `svc-ledger` — found earlier; the real surface was `registerS2sHttp`, not the
   tRPC plugin.
2. **`svc-protocol` — found this session.** It imported `fastifyTRPCPlugin`,
   built `appRouter`, built `createEdgeContext`, asserted the §22 sovereignty
   law at boot… and never called `app.register`. All twelve procedures were
   unreachable. `docs/TRACKER.md` records `protocol.smart-accounts` as ✅
   "self-mounts /trpc". It did not. **Fixed on the rebrand branch.**
3. `svc-indexer` mounts correctly, but the **edge had no route to it**, so every
   chain query 404'd at the door. Separately, `svc-dex` called it on **4012**
   when it listens on **4013**. Both fixed.

`workspace-sync` check 5 exists to catch exactly the port mismatch — but it only
inspects the **edge's** environment block. A service-to-service URL anywhere
else is outside its coverage. **That gap is still open and is worth closing.**

A health check that does not exercise the router cannot distinguish "up" from
"up and serving". Worth considering a readiness probe that hits one real
procedure.

**Reachable but refused, for two different reasons**

- `p2p` offers — 403, but the scope _is_ held; the jurisdiction matrix demands
  verification tier `basic`. Different fix entirely.

**DEX**

## What the rebrand actually did

- **English only.** Not defaulted — removed. The Chinese locale file is deleted
  and the language is hard-wired in the store, so no stored preference or stale
  commit can put a customer back into Chinese. 977 translations, 181 Chinese
  comments stripped. Verified zero CJK.
- **Black and orange.** 774 colours remapped. Market up/down deliberately
  untouched — a trader reads those as direction, not branding.
- **Design layer** at `05_Web_Front/src/assets/css/intafaced.css`: palette as
  custom properties, glass surfaces, radii, elevation, tabular figures. iView's
  light defaults are overridden explicitly because its white dropdowns and blue
  focus rings otherwise punch through a black page.
- **Vendor identity gone.** Logos were literal vendor wordmarks — deleted and
  replaced. `brand-scan` clean across 491 files. Attribution stays in the vendor
  tree's `LICENSE`/`NOTICE`, which the scan exempts by design. **Do not delete
  those** — that is the provenance record for Apache-2.0 code.

The scripts that did it are committed under `vendor/upstream-exchange/` (`rebrand`,
`retheme`, `translate`, `english-only`, `strip-comments`, `punctuation`,
`repair-bind`, `scan-cjk`, `extract-cjk`) so the work is reproducible and
auditable rather than a 50,000-line diff you have to take on faith.

## Things that bit me, so they do not bite you

**`build/` was never in git.** The root `.gitignore` has a blanket `build/`
rule; both vendored front-ends keep their webpack **config** there, not build
output. All 13 files were silently dropped when the vendor tree was committed,
so the app could not start from a clean clone — `npm run dev` died on a missing
`webpack.dev.conf.js`. Nothing in CI noticed because nothing in CI builds them.
Restored, with a `.gitignore` negation and the reason written down.

**Do not run PowerShell `Get-Content`/`Set-Content` over these files.** In 5.1
they read UTF-8 as ANSI when there is no BOM and write the mojibake back.
It corrupted ten files and webpack died on `Unexpected character '€'`. Every
rewrite script here reads and writes UTF-8 explicitly.

**Do not strip spaces before `:` in `.vue` files.** A punctuation cleanup did,
and turned `<div :class>` into `<div:class>` — 894 bindings, all rejected by the
template compiler. `repair-bind.mjs` fixes that class of damage.

**`node_modules` for the shell lives outside the repo.** The dev container
bind-mounts it from
`plug-x-inta-worktrees/feat-upstream-exchange-integration/vendor/upstream-exchange/05_Web_Front/node_modules`.
Recreating the container without that mount wipes them.

**Port 8080 is Apache** (EDB Postgres) on this machine. The shell runs on
**8090**. Docker will happily bind 8080 on IPv6 only while the browser reaches
Apache on IPv4 — which looks exactly like "the app is serving the wrong page".

## Still open

1. **The Java backend is up, but the markets are empty.** `ucenter`, `market`,
   `exchange-api` and `otc` are all running now, and `/market/symbol-thumb`
   returns the seeded BTC, ETH, SOL and XRP USDT pairs — but every price is
   `0` because no trade has ever matched. The chart has a datafeed and no bars.
   Seeding real candles, or pointing the datafeed at an external venue for
   history, is the next visible win.
2. **`svc-trade` does not check trading hours.** `isInstrumentOpen` exists and is
   tested, but the order-create path never calls it — a weekend EUR/USD order
   would be accepted today. Natural next branch.
3. **Commodities and forex are Fiat Plane only.** A Protocol Plane listing needs
   an oracle-priced synthetic that does not exist yet. Flipping it later is one
   array and one seed row. It was not faked.
4. **The sanctions blocklist is empty.** Screening works and screens nothing.
   This needs counsel before a public DEX — a compliance decision, not an
   engineering one.
5. **Scope issuance for `bank` and `blueprint`** (above).
6. **Hot reload does not work over the Windows bind mount.** `poll: false` in
   `05_Web_Front/config/index.js` means the dev server's watcher misses changes
   and every edit needs `docker restart intafaced-shell-web`. Setting
   `poll: 1000` would fix it; left alone so far because it changes dev-server
   behaviour for everyone.
7. **Nothing has been checked in a browser.** All verification this session was
   compile-level and endpoint-level — HTTP status, JSON payloads, CJK scans,
   test suites. No one has actually looked at the rendered terminal.
8. **A probe account was registered in the dev identity database**
   (`ix_probe_agent@example.com`) to get ground truth on scopes. Delete it if
   that database is not disposable.
