## Broken, fixed here

**1 · The kill-switch was bypassed by a dot segment.** The guard prefix-matched
the raw target; the proxy re-read the request with `new URL`, which removes dot
segments. `POST /api/trade/../identity/trpc/auth.login` was "trade" to the guard
and "identity" to the upstream, so a halted module kept serving — with
`/admin/status` still reporting it disabled and no 503 logged. → **PR #1071**

**2 · A tRPC batch hid a create behind a trailing cancel.** `procedureLeaf` read
only the last leaf of the captured list, so `orders.create,orders.cancel` was
allowed through a halted module and `orders.cancel,orders.create` was not. The
attacker chose the order. `@trpc/server` batches by default and no service
disables it. → **PR #1071**

Both fixes are pure functions, because the existing suite **cannot** see either
bug: every kill-switch test drives `app.inject()`, and `light-my-request`
normalises the URL before Fastify sees it. A test written in that harness passes
and proves nothing.

Checked rather than assumed: `new URL` **does** collapse `%2e%2e` and `%2E%2E`
like `..` (ran it — the first draft asserted the opposite and was wrong). What
it does not collapse is a dot segment behind an encoded slash (`..%2f`), which
is now refused. An ordinary encoded slash — a CCXT symbol like `BTC%2FUSDT` — is
deliberately **not** refused, because those are the release routes that let
users out during an incident.

## Broken, parked — and why each is not an agent call

**3 · `edge.gateway` is a documented kill-switch that nothing reads.** README:95
promises a 503 from it. The string appears nowhere in `services/svc-edge/src/**`,
`edge` has no prefix in `UPSTREAMS` so the admin API refuses to arm it, and
`packages/config/src/flag-enforcement.test.ts:248` asserts the opposite of the
README in its own title. Same class as the dead-letter promise closed in #1059.
**Parked:** deleting a documented operator control and building one are both
product decisions, not a patch.

**4 · The README says rate limiting does not exist. It exists and is on by
default.** README:107 lists it under "Not built yet"; `EDGE_RATE_LIMIT_ENABLED`
defaults **true** at 300/60s, and none of the four throttle variables appear in
the Configuration table. The consequence is not cosmetic: `docker-compose.apps.yml`
sets no `EDGE_TRUST_PROXY` while nginx proxies the whole product shell to the
edge, so with `trustProxy` unset **every caller shares one bucket** — the
self-DoS the code's own docstring warns about, invisible to anyone reading the
README. **Parked:** the doc fix is trivial, but the deployment fix
(`EDGE_TRUST_PROXY`) is an operator call about topology.

**5 · `/ready` gives away the halted-module list.** The CORS preflight ordering
exists specifically so _"an unauthenticated caller cannot read off which modules
an operator has halted"_, and it works. `index.ts:191` then publishes
`disabledModules` on unauthenticated `/ready`, which is a CORS surface, exempt
from the throttle, and published on the host. Meanwhile the audit trail is
asserted operator-only because _"an incident timeline is not public."_
**Parked:** whether the halted list is sensitive is a product call — the service
currently answers it two contradictory ways, and someone has to pick one.

**6 · The README route table lists 9 of 16 prefixes.** Missing `/api/v1` (the
public CCXT path that places and cancels real orders), `/api/dex`,
`/api/indexer`, `/api/notify`, `/api/academy`, `/api/support`. It understates
the front door's attack surface by six services. **Parked:** doc-only, and it
belongs with the rate-limit doc correction (#4) in one pass.

**7 · "Hop-by-hop headers must not be proxied" strips one of them.**
`principal-exchange.ts:71` claims the class; only `connection` (plus `host` and
`content-length`) is stripped. `transfer-encoding`, `te`, `trailer`, `upgrade`,
`keep-alive` and `proxy-authorization` are forwarded. **Parked:** no exploit
found — undici may reject some outbound — so this is a comment that overstates
the code, and the fix needs a live upstream to validate.

## Declared and never emitted

- **`edge.gateway`** — the real instance, see #3.
- **`ExchangeResult.rejected: 'malformed'`** — requires `AuthError('token.malformed')`,
  which is thrown only when a token verifies against our own secret and then
  fails its claims schema. An attacker's garbage lands as `'invalid'`. Reachable
  only if svc-identity mints a wrong-shaped token; no test asserts it.

## Executed by nothing

`src/index.ts` has **no test at all**. `control-plane.ts:9` explains why
(importing it boots a real server) and moves two guards out — but four
behaviours stayed behind and run in no test: `edge.no_route` from the proxy;
`edge.upstream_unavailable` (the 502-not-500 rule, which the vendored JS client
branches on); the `UPSTREAM_TIMEOUT_MS` abort that README:104 promises; and the
`/ready` payload README:16 sells to operators.

Also: the registration ORDER in `index.ts` — CORS → helmet → rate-limit →
kill-switch → routes — is a stated control held together by two test fixtures
that hand-copy it and say so in a comment. Nothing checks `index.ts` still makes
those calls. And no test asserts the edge's env schema still **excludes**
`INTERNAL_SERVICE_SECRET` / `DATABASE_URL` / `NATS_URL`; the property holds today
by reading `env.ts`, and nothing stops a future merge adding one.

## Could NOT break, having tried

Reaching `/admin/*` through the proxy (`/api/../admin/kill-switches` normalises,
`resolve()` returns null, 404). Reaching svc-ledger or svc-matching from a
browser — no prefix exists and no traversal creates one. Escaping the prefix
into the upstream URL: `..` cannot survive into the concatenation, so the SSRF
shape is closed. The reserved-header strip, in every casing and array form, with
and without a valid token. Wildcard or credentialed CORS — `parseOriginList`
rejects `*`, `null`, trailing slashes, paths, userinfo, explicit default ports
and duplicates, and throws rather than skipping; this file is the strongest
thing in the service. Preflight as a route oracle. Rate-limit allow-list bypass.
A fail-open limiter — counters are in-process, there is no store to lose, which
is the right shape. `/admin/*` authorisation, looked at specifically for the
classic "guard throws a type the catch does not handle, so a 403 becomes a 500":
it is not there.

Two things noted and deliberately not called findings: `OPTIONS /api/*` is
unmetered by design, and unmatched URLs skip the limiter because Fastify's
default 404 handler does not run the plugin hook. Both cost the edge process
only.
